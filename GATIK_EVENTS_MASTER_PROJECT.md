## Design constitution

- Warm paper `#F6F1E8`, deep ink `#24211D`, terracotta `#B85C46`, coral `#E65B45`, mustard `#D9A928`, pale sage `#DDE5D7`.
- Instrument Serif for display, Manrope for body/UI, mono only for metadata.
- Warm editorial neo-brutalism: sharp geometry, strong rules, purposeful asymmetry, restrained hard shadows.
- Layered radial aurora with reduced-motion fallback; no neon SaaS gradient.
- WCAG 2.2 AA target, visible focus, 44px minimum touch targets, no hover-only interactions.
- Test targets: 360, 375, 390, 430, 768, 1024, and 1440px.

## Architecture

- Next.js App Router, React, TypeScript, Tailwind CSS.
- Supabase PostgreSQL with RLS; Supabase Auth is not used by the application.
- Custom server-side authentication, Argon2id password hashes, opaque server sessions, Resend email.
- Short-lived ES256 application JWTs integrate authenticated requests with Supabase RLS.
- Server Components by default; validated server actions/RPCs for mutations.
- Playwright and Vitest for testing; Vercel for hosting.

## Security invariants

- Deny by default; verify identity, event membership, role, and object scope server-side and in RLS.
- Never expose a service/secret key to a browser.
- Passwords, session tokens, verification tokens, reset tokens, and invitation tokens are never stored as plaintext.
- Sensitive multi-row changes use transactions/RPCs and audit records.
- Public pages expose only published event content.
- The service worker never caches authenticated pages, API responses, participant data, or writes.
- Production changes, DNS changes, signing-key rotation, and data migrations require explicit owner approval and backup.
